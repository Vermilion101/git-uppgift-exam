Den största skillnaden mellan att spara i GIT och på Visual Studio är att när man sparar i VS så skriver man över det den sparade filen med det nya inehållet medans GIT sparar en commit (ägonblicksbild). GIT sammlar dessa commits i en historik och man kan återställa filen till dem tillstånden som sparats där när som helst. I t.ex. den här koden sulle jag kunna gå tillbaka till startkoden med 3 TODOS eftersom jag gjorde en commit innan jag började skriva över den, medans om jag bara hade sparat normalt i VS så hade det sparade tillståndet överskrivits för länge sen.

Fråga 2:
Git status är ett kommando du kan skriva i konsolen för att se en status raport av arbetsflödets tillstpånd just nu och GITs relation med arbetsytan på VS det vill säga vilken branch man är på, filer som har ändringar i sig och added filies etc. Git add är ett kommando man kan skriva i konsolen för att göra en "staging" av en eller flera filer vilket inebär att man markerar dem och deras ändringar för hantering i git. Git commit är ett kommando som tar de filer som är i staging tillståndet och gör en ögonblicksbild av varje fil. git gör det bara med filer i staging så att det inte är oklart vilka filer som man gör en commit på och undviker att man gör en commit på en fil man inte vil göra det på. Skulle man försöka göra en commit utan att ha några filer i staging så får man medelandet "no changes added to commit", det räcker alltså inte att bara göra en ändring utan man måste markera dem.

Frpga 3:
Största skillnaden mellan mappen på datorn och repot på github är att mappen på datorn är liogger lokalt på datorn medasn repot på github är i molnet. Det är därför en bra idé att koppla det lokala repot på datorn till ett repo i molnet på github så att man kan på en annan dator hämta arbetsflödet och fortsätta där man slutade. För att uppdatera repot i molnet använder man kommandot git push vilket uppdaterar historiken med de nya commit som har gjorts lokalt. Om man har glömmt att staga och commita sina ändringar innan man skriver git push så kommer git att svara "everything up-to-date" eftersom git push skickar bara upp commits i molnet och det finns inga filer markerade med git add så git anser att det inte finns några ändringar som är redo för att hanteras med git.
